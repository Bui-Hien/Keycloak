1. KEYCLOAK LÀ GÌ ?

Keycloak là nền tảng Identity and Access Management (IAM) mã nguồn mở được phát triển bởi Red Hat.

Keycloak giúp tập trung việc xác thực và phân quyền thay vì mỗi hệ thống tự xây dựng chức năng đăng nhập.

Tính năng chính

  • Single Sign On (SSO)
  • OAuth2
  • OpenID Connect
  • SAML
  • MFA
  • LDAP
  • Active Directory
  • Social Login
  • User Federation
Một người dùng đăng nhập một lần và có thể truy cập nhiều hệ thống.

10B. CUSTOM FRONTEND LOGIN FORM (DIRECT GRANT)

Trong một số trường hợp, doanh nghiệp muốn thiết kế Form đăng nhập trực tiếp tại giao diện Frontend (React, Vue, Angular...) thay vì chuyển hướng (Redirect) sang trang mặc định của Keycloak.

Để thực hiện điều này, chúng ta sử dụng luồng Resource Owner Password Credentials Grant (Direct Access Grant) của OAuth2 để trao đổi trực tiếp username/password lấy token qua REST API của Keycloak.

Luồng Direct Grant không được khuyến nghị cho các dự án ứng dụng công cộng (public clients) vì lý do bảo mật (Frontend có thể nhìn thấy và can thiệp trực tiếp vào thông tin đăng nhập của người dùng). Hãy cân nhắc kỹ trước khi sử dụng.

Bước 1: Bật Direct Access Grants trên Keycloak Console

Mặc định, Keycloak có thể chặn yêu cầu trực tiếp này. Bạn cần cấu hình Client trên Keycloak:

  • Vào Clients → Chọn Client ID của bạn (ví dụ: hienbx_fe).
  • Trong phần Capability config, tìm và bật toggle Direct Access Grants Enabled.
  • Bấm Save để áp dụng.

Bước 2: Gửi Request Đăng Nhập từ Frontend (Axios)

Frontend sẽ hiển thị Form đăng nhập tự thiết kế và gửi yêu cầu POST đến endpoint token của Keycloak với Content-Type là application/x-www-form-urlencoded: 


import axios from 'axios';

async function loginDirectly(username, password) {
  const tokenUrl = 'https://keycloak.hiendev.online/realms/hienbx/protocol/openid-connect/token';
  
  // Tạo form data body
  const params = new URLSearchParams();
  params.append('client_id', 'hienbx_fe');
  params.append('grant_type', 'password');
  params.append('username', username);
  params.append('password', password);
  params.append('scope', 'openid profile email');

  try {
    const response = await axios.post(tokenUrl, params, {
      headers: {
        'Content-Type': 'application/x-www-form-urlencoded'
      }
    });

    const { access_token, refresh_token, id_token, expires_in } = response.data;
    
    // Lưu token vào LocalStorage/SessionStorage hoặc HttpOnly Cookie
    localStorage.setItem('access_token', access_token);
    localStorage.setItem('refresh_token', refresh_token);
    
    console.log('Đăng nhập thành công!', response.data);
    return response.data;
  } catch (error) {
    console.error('Đăng nhập thất bại:', error.response?.data || error.message);
    throw new Error('Sai tài khoản hoặc mật khẩu.');
  }
}

Bước 3: Gửi Refresh Token để duy trì đăng nhập

Khi Access Token hết hạn, dùng Refresh Token gửi POST tương tự để làm mới token: 


async function refreshToken(storedRefreshToken) {
  const tokenUrl = 'https://keycloak.hiendev.online/realms/hienbx/protocol/openid-connect/token';
  
  const params = new URLSearchParams();
  params.append('client_id', 'hienbx_fe');
  params.append('grant_type', 'refresh_token');
  params.append('refresh_token', storedRefreshToken);

  const response = await axios.post(tokenUrl, params, {
    headers: {
      'Content-Type': 'application/x-www-form-urlencoded'
    }
  });

  return response.data; // Trả về access_token và refresh_token mới
}

23. LOGIN THEME

Keycloak hỗ trợ tùy biến giao diện đăng nhập (Login Theme) theo nhận diện thương hiệu của doanh nghiệp (Logo, màu sắc, phông chữ, bố cục).

Cấu trúc thư mục Theme

Một Theme tùy biến cần được đặt trong thư mục themes/ của Keycloak với cấu trúc tối thiểu như sau: 

themes/
└── company-theme/              
    └── login/                  
        ├── theme.properties    
        ├── login.ftl           
        ├── template.ftl        
        └── resources/          
            ├── css/
            │   └── custom-style.css
            ├── img/
            │   └── logo.png
            └── js/
                └── main.js

Chi tiết các File cấu hình

1. File theme.properties

Định nghĩa các thuộc tính của theme, liên kết CSS/JS và chỉ định theme cha để kế thừa: 


# Kế thừa từ theme base hoặc keycloak mặc định để không phải viết lại tất cả file ftl
parent=keycloak

# Nạp file CSS tùy biến
styles=css/custom-style.css

# Nạp file JS tùy biến (nếu có)
scripts=js/main.js

# Khai báo các class CSS để override lại styles mặc định của Keycloak
kcHtmlClass=login-pf
kcLoginClass=login-card-pf

2. File login.ftl (Freemarker Template)

Đây là mã nguồn HTML + Freemarker (FTL) định nghĩa Form nhập tài khoản mật khẩu: 


<#import "template.ftl" as layout>
<@layout.registrationLayout displayMessage=!messagesPerField.existsError('username','password') displayInfo=realm.password && realm.registrationAllowed && !registrationDisabled??; section>
    <#if section = "header">
        <!-- Phần tiêu đề hiển thị trên thẻ card -->
        <h3>Đăng nhập vào hệ thống</h3>
    <#elseif section = "form">
        <!-- Form đăng nhập chính -->
        <form id="kc-form-login" onsubmit="login.disabled = true; return true;" action="${url.loginAction}" method="post">
            <div class="form-group">
                <label for="username">Tên đăng nhập hoặc Email</label>
                <input id="username" class="form-control" name="username" value="${(login.username!'')}" type="text" autofocus autocomplete="off" />
            </div>

            <div class="form-group">
                <label for="password">Mật khẩu</label>
                <input id="password" class="form-control" name="password" type="password" autocomplete="off" />
            </div>

            <div class="form-actions">
                <input class="btn btn-primary" name="login" id="kc-login" type="submit" value="Đăng nhập"/>
            </div>
        </form>
    </#if>
</@layout.registrationLayout>

Cách triển khai và kích hoạt Theme

Triển khai với Docker

Nếu chạy Keycloak bằng Docker, bạn cần gắn (mount) thư mục theme vào container: 


services:
  keycloak:
    image: quay.io/keycloak/keycloak:26.2.4
    volumes:
      - ./themes/company-theme:/opt/keycloak/themes/company-theme
    ports:
      - 8080:8080

Kích hoạt trong Keycloak Admin Console

  • Truy cập vào Keycloak Admin Console.
  • Chọn Realm của bạn (ví dụ: hienbx).
  • Vào menu Realm Settings từ thanh menu bên trái → Chọn tab Themes.
  • Tại mục Login Theme, chọn theme tùy biến của bạn (ví dụ: company-theme).
  • Bấm Save. Hãy thử logout và mở lại trang login để tận hưởng giao diện mới.

44.3. Identity Providers

Identity Providers (IdP) cho phép người dùng đăng nhập bằng các tài khoản định danh bên ngoài. Có hai nhóm chính: Social Login (Google, Facebook, GitHub, Apple) và Enterprise Identity Providers (liên kết với các hệ thống Keycloak khác, Azure AD, Okta qua giao thức chuẩn OpenID Connect hoặc SAML 2.0).

44.4. User Federation

User Federation kết nối cơ sở dữ liệu người dùng bên ngoài với Keycloak. Thay vì phải di chuyển (migrate) hàng ngàn tài khoản nhân sự từ Active Directory (AD) hay LDAP có sẵn của công ty vào cơ sở dữ liệu riêng của Keycloak, bạn có thể cấu hình User Federation để Keycloak truy vấn, xác thực trực tiếp và đồng bộ hóa tài khoản từ các nguồn ngoài này theo thời gian thực.

Tab Connection Settings (Kết nối LDAP/AD)

Thiết lập đường truyền vật lý kết nối với máy chủ LDAP:

  • Bind DN / Bind Credential: Tài khoản quản trị của LDAP có đủ quyền đọc để thực hiện truy vấn danh sách người dùng.

Tab User Schema (Cấu trúc dữ liệu)

Ánh xạ cấu trúc dữ liệu LDAP:

  • Users DN: Node gốc chứa người dùng trong danh mục LDAP.
  • Username Attribute: Thuộc tính đóng vai trò là tên đăng nhập (ví dụ: `sAMAccountName` đối với Active Directory, `uid` đối với OpenLDAP).
  • Edit Mode: `READ_ONLY` sẽ không cho phép sửa đổi thông tin user từ Keycloak; `WRITABLE` sẽ tự động ghi đồng bộ ngược lại các thay đổi thông tin (như đổi mật khẩu) lên máy chủ LDAP gốc.

Tab Sync Settings (Chu kỳ đồng bộ)

Cấu hình đồng bộ chạy ngầm (Background Sync):
